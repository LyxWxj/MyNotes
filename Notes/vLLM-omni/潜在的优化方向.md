现在让我为你总结一下从 vllm-omni 仓库 PR 区搜索到的 Diffusion 模型推理优化的案例和方向：

## Diffusion 模型推理优化总结

根据 vllm-omni 仓库的 PR 分析，Diffusion 模型推理优化主要从以下几个方面入手：

### 1. **CUDA Graph 优化** 🚀

**案例**: PR #4927 - Add CUDA Graph runner for Cosmos3 diffusion transformer forward

**优化原理**:

- 将多个 CUDA kernel 调用合并为一个 `cuGraphLaunch` 调用
- 减少 CPU 到 GPU 的调度开销
- 特别适合固定 shape 的推理场景

**效果**:

- Cosmos3-Nano, 512x512, 20 steps: **+42.2% 吞吐量提升**
- 延迟降低 **29.7%**
- Stage 0 Gen 时间减少 **35.9%**

**关键实现**:

- `DiffusionCUDAGraphRunner` 和 `DiffusionCUDAGraphConfig`
- 通过 `--enable-cuda-graph` 和 `--cuda-graph-config` CLI 参数控制
- 支持 warmup 和 graph 生命周期管理

---

### 2. **torch.compile 优化** ⚡

**案例**: PR #4603 - Add configurable diffusion compile granularity

**优化原理**:

- 区域编译 (regional) vs 全模型编译 (full)
- 固定 shape 时使用 `dynamic=False` 获得更好性能
- 减少 CPU 端 overhead

**效果**:

- LTX-2.3 T2V: **-12.83% 延迟**, **+14.72% QPS**
- CPU 事件减少 **28.1%**, `aten::empty` 减少 **44.5%**

**关键配置**:

```python
--diffusion-compile-granularity regional | full
--[no-]diffusion-compile-dynamic
```

---

### 3. **TeaCache 缓存优化** 🍵

**案例**: PR #2682 - Add TeaCache for HunyuanVideo-1.5

**优化原理**:

- 利用扩散模型相邻步骤的相似性
- 缓存并复用前一步的计算结果
- 通过多项式系数预测跳过计算的时机

**效果**:

- HunyuanVideo-1.5 T2V: **1.42x 加速** (284.1s → 200.1s)
- I2V: **1.42x 加速** (190.3s → 134.0s)
- LPIPS 质量损失在可接受范围内

**使用方式**:

```bash
--cache-backend tea_cache --tea-cache-thresh 0.3
```

---

### 4. **FP8 量化** 📉

**案例**: PR #4961 - Add FP8 dynamic quantization for MagiHuman

**优化原理**:

- 使用 FP8 (8 位浮点) 替代 BF16/FP16
- 动态在线量化，无需校准数据
- 减少显存占用和计算量

**效果**:

- MagiHuman: **35% 显存减少** (79.68 GiB → 51.98 GiB)
- 540p SR: **31% 显存减少**, LPIPS 0.0489
- 质量损失在可接受范围内 (LPIPS 阈值 0.1)

**支持的模型**:

- HunyuanImage3
- MagiHuman
- SenseNova-U1
- FLUX.1-dev text encoder

---

### 5. **异步输出优化** 🔄

**案例**: PR #4981 - Enable Diffusion Image models asynchronous output

**优化原理**:

- 将 D2H (Device→Host) 拷贝和 SHM 打包移到后台守护线程
- 主线程可以立即开始下一个请求的 forward
- 消除 GPU 空闲时间 (bubble)

**效果**:

- HunyuanImage3: **性能提升** (具体数据在 PR 中)
- QwenImage: **性能提升**
- 通过 `ENABLE_ASYNC_DIFFUSION_OUTPUT=1` 启用

---

### 6. **KV Cache 预取优化** 📦

**案例**: PR #4772 - Add step-mode KV prefetch

**优化原理**:

- 将 KV 预取从 step-bound 改为 fire-and-forget
- 在请求进入 DiT engine 时立即开始预取
- 利用队列等待时间进行后台数据传输

**效果**:

- Hunyuan-Image IT2I: **1.05x 加速**
- T2I: **1.03x 加速** (KV cache 较小)
- 通过异步传输减少 forward 时的等待

---

### 7. **Ring Attention 优化** 🔗

**案例**: PR #5187 - Optimize ring-flash-attention

**优化原理**:

- 双缓冲 KV 通信 (DoubleBufRingComm)
- 融合 Triton online-softmax merge
- 持久化 fp32 workspace

**效果**:

- Wan2.2-T2V-A14B, 832x480, 81f: **1.11x 加速**
- 1280x720, 81f: **1.08x 加速**
- 随着 ring degree 增加，优化效果更明显

---

### 8. **Dynamic Batching** 📊

**案例**: PR #4024 - Support dynamic batching for heterogeneous diffusion requests

**优化原理**:

- 允许不同分辨率、不同 text length 的请求在同一个 batch 中
- 使用 FlashAttention varlen 路径
- 减少 padding，提高 GPU 利用率

**效果**:

- HunyuanImage3 batch=8: **6.800x 生成加速**
- E2E 加速 **1.469x**

---

### 9. **Disaggregated VAE** 🧩

**案例**: PR #3208 - Support Qwen-Image disaggregated VAE

**优化原理**:

- 将 pipeline 拆分为 encode → denoise → decode 三个阶段
- 减少 denoise 阶段的显存压力
- 支持多实例并行

**效果**:

- 显存减少: denoise 阶段从 **58.66 GB** 降到 **38.42 GB**
- 多卡高并发场景下吞吐量提升 **10-15%**

---

### 10. **MoE Tiling 优化** 🎯

**案例**: PR #5190 - Support fine-tuned MoE tiling configs

**优化原理**:

- 针对特定硬件和输入 size 优化 Triton kernel 的 tiling 参数
- 使用 `VLLM_TUNED_CONFIG_FOLDER` 加载自定义配置
- 减少 kernel 执行时间

**效果**:

- HunyuanImage TP4: **+4.67% QPS 提升**
- IT2I: **+4.70% QPS 提升**

---

### 11. **Sequence Parallel 通信优化** 🌐

**案例**: PR #3939 - Reduce Ulysses communication overhead

**优化原理**:

- 利用 attention backend 原生 GQA 支持
- 避免物理复制 K/V heads
- 减少 all_to_all 通信量

**效果**:

- HunyuanImage3: **50% 通信量减少**
- E2E 延迟降低 **1.0%** (4 GPUs)

---

### 12. **Attention Mask 优化** 🎭

**案例**: PR #4645 - Skip attention-mask to avoid varlen path

**优化原理**:

- 对于某些模型，跳过 attention mask 计算
- 避免 varlen 路径的额外开销

**效果**:

- FLUX.2-dev 1304x1304: **-22.8% 延迟**
- HunyuanVideo-1.5 848x480: **-29.0% 延迟**

---

## 优化入手建议

根据这些案例，建议从以下方面入手：

1. **先做 profiling**: 使用 `torch.profiler` 或 `ncu` 找到瓶颈
2. **CUDA Graph**: 对于固定 shape，这是最直接的优化
3. **torch.compile**: 区域编译效果好，配置灵活
4. **TeaCache**: 对于多步骤推理，效果显著且实现简单
5. **FP8 量化**: 显存优化首选，质量损失可控
6. **异步化**: 对于高并发场景，异步输出效果明显
7. **KV 预取**: 对于 disaggregated serving，减少数据传输等待

这些优化可以组合使用，例如：`torch.compile + CUDA Graph + TeaCache` 可以获得叠加的优化效果。
