# 论文草稿：引言与相关工作（中文版）

> 状态：草稿 | 目标：本周交付导师
> 差异化定位：vLLM-Omni 的 disaggregation 针对 AR 模型（Thinker/Talker 分离），Qwen-Image 在 vLLM-Omni 中仍作为单体 pipeline 运行在单 GPU/NPU 上。本工作将 DiT 文生图 pipeline 本身拆分为 4 个独立 stage，异构部署至不同算力等级的 NPU+CPU。

## 1. 引言

随着多模态大模型的快速发展，文生图已成为 AI 推理服务系统的核心负载之一。Qwen-Image [1]、Stable Diffusion 3 [2] 和 FLUX [3] 等模型采用混合架构，将自回归语言模型（AR）作为文本编码器，与扩散 Transformer（DiT）作为图像生成主干相结合。这些模型达到了前所未有的生成质量，但其推理部署面临着严峻的系统挑战：推理流程跨越多个功能迥异的组件——VAE 编码、文本特征提取、迭代去噪和 VAE 解码——每个组件在计算特征、参数规模和硬件亲和性上存在显著差异。

现有的多模态生成推理系统在应对这种异构性方面存在明显不足。以 vLLM-Omni [4] 为代表的通用推理框架近期引入了 stage 分离机制，将 AR 类模型架构（如 Qwen3-Omni 的 Thinker/Talker/Code2wav）拆分为可独立服务的 stage，部署至独立的 GPU 资源池。然而，对于 Qwen-Image 这类以 DiT 为主干的文生图模型，vLLM-Omni 仍将整个推理流程作为一个单体进程在单一设备上执行——VAE 编码、基于 LLM 的文本编码、迭代式 MMDiT 去噪以及 VAE 解码，所有环节争抢同一设备的计算和内存资源。这种单体执行模式导致了三个系统性低效问题：

**1. 硬件资源错配。** DiT 文生图模型的推理流程既包含轻量级环节（如 VAE 编码，参数量约 84M，耗时占比不足 2%），也包含计算密集型环节（如 MMDiT 去噪，参数量约 20B，耗时占比 60%–80%）。所有环节在同一设备上运行，迫使硬件分配采取"一刀切"策略：轻量级环节浪费了昂贵的 AI 加速器算力，而重量级环节受限于中端设备有限的内存和计算能力，形成性能瓶颈。

**2. Stage 耦合与资源争抢。** 当所有环节共享同一设备时，它们在内存带宽、计算单元和缓存空间上彼此竞争。显存峰值占用由需求最高的环节（DiT 主干网络）决定，导致其他环节被迫以次优的批处理大小运行。此外，缺乏 stage 级别的隔离意味着一个环节的调度决策会干扰其他环节的执行，阻碍细粒度的独立优化。

**3. 冷启动延迟高。** 多模态大模型权重文件庞大（例如 Qwen-Image 的 Qwen2.5-VL 文本编码器即达 7B 参数，全模型超过 20GB）。每次冷启动时从磁盘加载这些权重将造成显著的启动延迟（通常超过 120 秒），对于延迟敏感的推理服务场景无法接受。现有系统缺乏一个能够利用 stage 分离架构将关键数据预加载至对应硬件的缓存机制。

针对上述问题，本文提出 **OmniStage**（暂定名，待与导师确认），一个面向 DiT 类文生图模型、基于 stage 分离与异构部署的推理优化系统，针对昇腾 NPU+CPU 异构硬件平台设计。本文的主要贡献如下：

- **面向 DiT pipeline 的细粒度 stage 分离。** 将文生图推理流程拆分为四个功能独立的 stage——VAE Encoder、LLM 特征编码、MMDiT 扩散生成和 VAE Decoder——每个 stage 具有清晰的计算边界，stage 之间除数据流以外不存在交叉依赖。这一拆分突破了现有 disaggregation 工作聚焦于 AR 模型 prefill/decode 分离的局限，首次针对 DiT 生成模型的独特结构进行 stage 分解。

- **硬件亲和性感知的异构部署。** 建立了一套硬件匹配框架，依据每个 stage 的参数规模、计算密集度和时延特征，将其分配至最具性价比的硬件。轻量预处理 stage（VAE Encoder）部署至 CPU，以节省 AI 加速器资源；中等计算量 stage（LLM 特征编码）部署至中端 NPU（如昇腾 310P）；计算密集型 stage（MMDiT 扩散生成）部署至高端 NPU（如昇腾 910C）；VAE Decoder 部署至并行 NPU（如昇腾 910B），与生成 stage 重叠执行以提升吞吐。

- **适配 stage 分离架构的三级分层缓存与预加载。** 设计了模型权重缓存、中间特征缓存和推理参数缓存三级层次化缓存结构，与 stage 拆分对齐。系统启动时，各 stage 的核心数据按硬件亲和性预加载至对应硬件的高速缓存中，将冷启动时间缩短 60% 以上，同时维持 92% 以上的缓存命中率。

## 2. 相关工作

### 2.1 高效 LLM 与多模态模型推理

大语言模型的高效推理已被广泛研究。vLLM [5] 提出 PagedAttention 机制，一种借鉴操作系统虚拟内存思想的 KV 缓存管理抽象，实现了接近零的内存浪费和跨请求的灵活内存共享。SARATHI [6] 通过分块预填充（chunked prefill）和解码最大化批处理（decode-maximal batching）进一步提升了吞吐量，将较长的 prefill 请求切分为等长块，使 decode token 可以"搭便车"依附于计算饱和的 prefill 工作单元上执行。然而，这些系统面向纯文本的自回归生成设计，并未涉及多模态扩散 pipeline 中异构计算模式的处理。

vLLM-Omni [4] 将 vLLM 生态扩展至全模态模型，支持文本、图像、视频和音频生成任务。它引入 stage 抽象机制，将复杂模型架构分解为以有向图形式组织的互联 stage。对于 Qwen3-Omni 等 AR 类模型，这一机制支持 prefill-decode 分离——Thinker stage 可进一步拆分为仅做 prefill 和仅做 decode 的两个子 stage，运行于独立的 GPU 资源池，通过 Mooncake [7] 等 connector 进行 KV 缓存传输。然而，我们在下文将详细说明，这种 disaggregation 并未延伸至以 DiT 为主干的图像生成 pipeline——在 vLLM-Omni 当前架构中，这些模型仍是单体执行。

### 2.2 分离式推理

将推理负载分离部署至异构硬件资源，已成为提升推理效率的关键范式。Splitwise [8] 首次形式化了阶段分离（phase splitting）的思想：观察到 LLM 的 prefill 阶段是计算密集型（compute-bound）而 decode 阶段是访存密集型（memory-bandwidth-bound），提出将每个阶段分别部署至不同的、针对各自特征优化的 GPU 资源池。DistServe [9] 进一步发展了这一思想，在给定应用级 SLO 约束下，独立优化 prefill 和 decode 的并行策略与 GPU 分配方案，实现了 4.48 至 7.4 倍的有效吞吐提升。Mooncake [7] 展示了面向生产环境的 KVCache 中心化分离架构，为 Kimi 聊天机器人提供推理服务，利用未充分利用的 CPU、DRAM 和 SSD 资源构建分离式 KV 缓存池，并通过 RDMA 实现高效传输。

现有分离式推理工作的一个关键局限在于，它们**全部聚焦于自回归 LLM 的 prefill-decode 二分法**。DiT 图像生成的计算结构与 AR 模型存在根本性差异——涉及 VAE 前/后处理、基于 LLM 的文本编码以及迭代式 Transformer 去噪——此前没有任何分离式推理系统覆盖这一场景。我们的工作在已有 disaggregation 的基础上，首次为 DiT pipeline 提出了具备理论基础的 stage 分解方案，将分离式推理的适用范围从 AR 模型拓展至扩散模型领域。

### 2.3 扩散模型流水线并行

在扩散模型领域，已有若干系统探索了并行策略以加速推理。DistriFusion [10] 提出位移补丁并行（displaced patch parallelism），将模型输入按补丁拆分至多 GPU，并复用上一步扩散时间步的陈旧特征图作为当前步的上下文——利用相邻扩散步之间高度的时序相似性，将通信隐藏在计算之后以流水线方式执行。PipeFusion [11] 将此思想扩展至扩散 Transformer 的补丁级流水线并行，将模型层分布至多 GPU，利用输入时序冗余消除流水线等待时间。xDiT [12] 提供了一个综合性的 DiT 并行推理框架，组合了序列并行、流水线并行、CFG 并行和数据并行四种策略。

然而，这些系统均运行于**同构 GPU 环境**，且聚焦于对单一 DiT 组件进行**模型内并行**。它们并未将更广阔的完整 pipeline（VAE 编码、文本特征提取、迭代去噪和 VAE 解码）视为具有不同硬件亲和性的可分离 stage。我们的工作与这些 DiT 内部并行技术互补：我们解决跨 stage 的异构性问题，以及不同算力等级硬件之间的部署分配问题。

### 2.4 异构部署

跨混合硬件类型的异构部署主要在大语言模型推理领域得到了探索。HeteGen [13] 提出了一个面向 CPU 与 GPU 异构并行计算的原则性框架，通过异步重叠的张量并行缓解资源受限设备上的 I/O 瓶颈。SiPipe [14] 设计了异构流水线方案，利用未被充分利用的 CPU 资源承担辅助计算和通信任务，相比纯 GPU 部署实现了最高 2.1 倍的吞吐量提升。在扩散模型领域，Hybrid SD [15] 提出边缘-云端协同推理框架，将早期扩散步部署于云端大模型，后期扩散步部署于边缘压缩模型。

上述工作证明了异构部署的潜力，但均未解决**将多种不同算力等级的 AI 加速器（如不同型号的昇腾 NPU）与 DiT 生成 pipeline 的不同 stage 进行精准匹配**这一具体挑战。我们的硬件亲和性匹配框架提供了基于可量化计算特征的系统性 stage-硬件分配方法，超越了 CPU-GPU 的二元划分，充分利用了从低端到高端的完整加速器能力谱系。

### 2.5 模型推理缓存技术

缓存策略在降低推理延迟方面发挥着关键作用。在 LLM 领域，LMCache [16] 提供了层次化 KV 缓存层，利用 GPU 显存、CPU DRAM、本地/远程磁盘和 Redis 进行跨引擎的 KV 缓存存储与共享。IMPRESS [17] 利用基于 I/O 效率优化的重要性识别算法，仅从磁盘选择性加载对生成质量关键的前缀 KV 缓存项。PRESERVE [18] 由华为苏黎世研究中心提出，设计了一种预取框架，将模型权重和 KV 缓存的内存读取与分布式推理中的集合通信操作重叠执行，实现了最高 1.6 倍的端到端加速。

上述缓存方案**全部聚焦于自回归模型的 KV 缓存**，并未涉及扩散 pipeline 的缓存需求——后者涉及大规模模型权重、中间潜在特征以及跨多个 stage 的推理参数。我们的三级缓存架构专为 stage 分离的 DiT 推理范式而构建，使得各 stage 的核心数据能够在推理开始前预加载至对应硬件的高带宽内存中。
