# 如何添加一个模型支持

## Step1: 准备模型代码

1. 引入模型代码：clone HuggingFace 的 `modeling_*.py` 作为改写起点
2. 对照已有模型：参考 `vllm/model_executor/models/llama.py` 等已存在的实现
3. 保留协议许可
4. 移除训练代码

> [!TIP]
> 直接从 HuggingFace Transformers 的 `src/transformers/models/<model>/modeling_<model>.py` 复制，然后逐步裁剪训练相关代码（loss 计算、gradient checkpointing 等），保留推理路径即可。

---

## Step2: 兼容 vLLM — prefix 机制

vLLM 要求所有模块在 `__init__` 里接受一个 `prefix` 字符串，通常等于模块在 `state_dict` 里的全名。

> [!IMPORTANT]
> **为什么需要 prefix？**
> 1. **运行时支持**：vLLM 的 attention 算子按全名注册，每个 attention 必须有唯一的 prefix
> 2. **量化支持**：运行时根据 prefix 匹配量化配置，决定该层是否走量化路径，从而支持非均匀量化

初始化代码：把 prefix 一路传下去

```python
from torch import nn
from vllm.config import VllmConfig
from vllm.model_executor.layers.attention import Attention

class MyAttention(nn.Module):
    def __init__(self, vllm_config: VllmConfig, prefix: str):
        super().__init__()
        self.attn = Attention(prefix=f'{prefix}.attn')

class MyDecoderLayer(nn.Module):
    def __init__(self, vllm_config: VllmConfig, prefix: str):
        super().__init__()
        self.self_attn = MyAttention(vllm_config, prefix=f'{prefix}.self_attn')

class MyModel(nn.Module):
    def __init__(self, vllm_config: VllmConfig, prefix: str):
        super().__init__()
        self.layers = nn.ModuleList([
            MyDecoderLayer(vllm_config, prefix=f'{prefix}.layers.{i}')
            for i in range(num_layers)
        ])

class MyModelForCausalLM(nn.Module):
    def __init__(self, vllm_config: VllmConfig, prefix: str):
        super().__init__()
        self.model = MyModel(vllm_config, prefix=f'{prefix}.model')
```

> [!NOTE]
> `VllmConfig` 中包含 `CacheConfig`、`ParallelConfig` 等信息，按需使用。

## Step3: 张量并行

替换思路：

| HF 原始层 | vLLM 并行层 |
|---|---|
| `nn.Embedding` | `VocabParallelEmbedding` |
| `nn.Linear`（LM Head） | `ParallelLMHead` |
| `nn.Linear`（FFN 第一层） | `MergedColumnLinear` |
| `nn.Linear`（Q/K/V） | `QKVParallelLinear` |
| `nn.Linear`（FFN 第二层 / O-Proj） | `RowParallelLinear` |

```python
from vllm.model_executor.layers.linear import (
    MergedColumnLinear, RowParallelLinear, QKVParallelLinear
)

class MyAttention(nn.Module):
    def __init__(self, vllm_config: VllmConfig, prefix: str):
        super().__init__()
        self.qkv_proj = QKVParallelLinear(prefix=f'{prefix}.qkv_proj')
        self.out_proj = RowParallelLinear(prefix=f'{prefix}.out_proj')
```

> [!NOTE]
> **并行层一览**

| 类名 | 切分方式 | 通信操作 | 典型用途 |
|---|---|---|---|
| `ReplicatedLinear` | 权重复制 | 无 | 小层，不需要省显存的场合 |
| `ColumnParallelLinear` | 沿输出维（列）切分 | 无 | FFN 第一层，Q/K/V 拆分 |
| `RowParallelLinear` | 沿输入维（行）切分 | AllReduce | FFN 第二层，输出投影 |
| `MergedColumnLinear` | 多个 ColumnParallel 合并 | 无 | SwiGLU 风格 FFN（gate+up） |
| `QKVParallelLinear` | Q/K/V 一起切分 | 无 | MHA/GQA 注意力的 QKV 投影 |
| `VocabParallelEmbedding` | 沿词表维度切分 | AllReduce | 替代 `nn.Embedding` |
| `ParallelLMHead` | 沿词表维度切分 | AllReduce | LM Head（输出投影） |

## Step4: 实现 load_weights — 把 HF Checkpoint 装进来

```python
from typing import Iterable, Tuple
import torch

def load_weights(self, weights: Iterable[Tuple[str, torch.Tensor]]):
    stacked_params_mapping = [  # (vllm_param, hf_weight, shard_id)
        ('.qkv_proj', 'q_proj', 'q'),
        ('.qkv_proj', 'k_proj', 'k'),
        ('.qkv_proj', 'v_proj', 'v'),
        ('.gate_up_proj', 'gate_proj', 0),
        ('.gate_up_proj', 'up_proj', 1),
    ]
    params_dict = dict(self.named_parameters())
    for name, loaded_weight in weights:
        for (param_name, hf_name, shard_id) in stacked_params_mapping:
            if hf_name not in name:
                continue
            name = name.replace(hf_name, param_name)
            param = params_dict[name]
            param.weight_loader(param, loaded_weight, shard_id)
```

> [!WARNING]
> 常见坑：
> 1. **映射遗漏**：HF 权重名和 vLLM 参数名不一致时，`params_dict` 里找不到会静默跳过，导致权重未加载
> 2. **shard_id 缺失**：合并的参数（如 gate+up）必须传 `shard_id`，否则只加载了其中一个
> 3. **未返回 `UnusedWeights`**：如果 checkpoint 中有 vLLM 不需要的权重（如训练用的 `lm_head`），需要显式处理或跳过，否则可能报错

> [!TIP]
> 调试时可以用 `--load-format dummy` 快速验证模型能否启动，不用等完整 checkpoint 加载。

## Step5: 注册模型 — 让 vLLM 找到你的实现

### 方式一：内置（Built-in）— 合入 vLLM 主仓库

- Fork vLLM 仓库并从源码编译
- 把模型放进 `vllm/model_executor/models/`
- 在 `registry.py` 的 `_VLLM_MODELS` 中注册
- 保持字典字母序
- 在 `supported_models` 文档中加入

### 方式二：外部（Out-of-tree）— 无需修改 vLLM 代码

```python
from vllm.model_executor.models import ModelRegistry

# 在插件入口注册
ModelRegistry.register_model(
    "MyModelForCausalLM",
    "my_package.models.my_model:MyModelForCausalLM",
)
```

> [!TIP]
> 若 import 会触发 CUDA 初始化，使用懒加载字符串形式（如上例的 `"my_package.models.my_model:MyModelForCausalLM"`），避免在注册阶段就占用 GPU 资源。

> [!CAUTION]
> 外部注册适合实验性 / 私有模型。如果模型要合入主仓库，必须走内置路径。

## Step6: 多模态接入 — 在文本模型基础上扩展

> [!IMPORTANT]
> 多模态模型需要实现 `SupportsMultiModal` 接口，并完成以下组件：

| 组件 | 基类 | 关键方法 | 作用 |
|---|---|---|---|
| 模型本身 | `SupportsMultiModal` | `get_placeholder_str` | 定义占位符 token（如 `<image>`） |
| 处理信息 | `BaseProcessingInfo` | `get_supported_mm_limits` | 声明支持的模态类型和数量上限 |
| Dummy 输入 | `BaseDummyInputsBuilder` | `get_dummy_text/data` | 构造 dummy 输入用于 shape 推断 |
| 处理器 | `BaseMultiModalProcessor` | 字段配置、prompt 更新 | 解析原始输入，更新 prompt |
| 注册 | `@MULTIMODAL_REGISTRY.register_processor` | — | 让 vLLM 发现处理器 |

参考实现：`LLaVA`、`Qwen3-Omni`、`Voxtral`、`Fuyu`

## Step7: embed_multimodal 与组件标记

> [!IMPORTANT]
> **核心思想**：把 HF 原本写在 `forward` 里的视觉编码 + 投影逻辑，搬到 `embed_multimodal`；文本嵌入与合并由 vLLM 默认实现自动处理。

```python
# 最小示例：一个带视觉编码器的 VLM
class MyVLMForCausalLM(nn.Module, SupportsMultiModal):

    # ── 组件标记：告诉 vLLM 各子模块用途 ──
    # （用于 tensor parallel / 量化 / 权重加载时识别角色）
    def __init__(self, vllm_config: VllmConfig, prefix: str):
        super().__init__()
        self.text_model     = MyLLM(vllm_config, prefix=f'{prefix}.model')
        self.vision_encoder = VisionEncoder(vllm_config, prefix=f'{prefix}.vision')
        self.mm_projector   = nn.Linear(1024, 4096)

    # ── embed_multimodal：把 HF forward 里的视觉逻辑搬到这里 ──
    def embed_multimodal(
        self,
        input_ids: torch.Tensor,                    # 含 <image> 占位符的 token 序列
        pixel_values: torch.Tensor | None = None,   # 图像像素值
        **kwargs,
    ) -> torch.Tensor:
        # ① 文本嵌入
        text_embeds = self.text_model.embed_tokens(input_ids)   # (B, N, D)

        # ② 视觉编码 + 投影（从 HF forward 搬来）
        if pixel_values is not None:
            vis_feat   = self.vision_encoder(pixel_values)      # (B, N_vis, D_vis)
            vis_embeds = self.mm_projector(vis_feat)            # (B, N_vis, D)

            # ③ 用视觉嵌入替换 <image> 占位符
            image_mask = (input_ids == IMAGE_TOKEN_ID)
            text_embeds[image_mask] = vis_embeds.flatten(0, 1)

        return text_embeds  # vLLM 框架自动接管后续 decoder + KV cache + 采样
```

> [!NOTE]
> **与 HF 的对比**
> | | HF `forward` | vLLM `embed_multimodal` |
> |---|---|---|
> | 文本嵌入 | `embed_tokens(input_ids)` | 相同 |
> | 视觉编码 | `vision_encoder(pixel_values)` | 相同，搬到这里 |
> | 投影对齐 | `mm_projector(vis_feat)` | 相同，搬到这里 |
> | 拼接合并 | `self._merge(...)` | 相同，搬到此处 |
> | 送入 LLM | `inputs_embeds=...` | vLLM 自动处理 |

## 附录：常见问题

### Q1: 滑动窗口注意力

> [!TIP]
> - 检查 `config.json` 中是否有 `layer_types` 字段
> - 在建模代码里逐层解析滑动窗口大小，传入 `Attention` 的 `per_layer_sliding_window` 参数

### Q2: Mamba & Mamba-like

> [!NOTE]
> 根据模型架构选择对应的基类：
>
> | 架构类型 | 基类 | 关键组件 | 参考实现 |
> |---|---|---|---|
> | 纯 Mamba | `IsAttentionFree` | `MambaMixer` / `MambaMixer2`，加入 `MODELS_CONFIG_MAP` | — |
> | Mamba + Attention | `IsHybrid` | 实现 `get_mamba_state_*` | `Jamba`、`Bamba` |
> | 类 Mamba 自定义 | `MambaBase` | 实现 `get_state_dtype/shape/attn_backend`，必要时注册 custom op | — |
