# 进阶主题：TMA、Warp Specialization、Pipelining

## 1. TMA (Tensor Memory Accelerator)

### 1.1 什么是 TMA？

TMA 是 Hopper 架构引入的 **硬件搬运引擎**。它能自动把数据从 GMEM 搬到 SMEM，不需要 warp 花指令去做。

```
没有 TMA（Ampere）:
  warp 0~7: 执行 LD.E.128 指令搬运数据（消耗指令配额）
  warp 8~31: 等待（浪费）

有 TMA（Hopper）:
  warp 0: 发出 TMA 指令（1 条指令描述整个 tile 的搬运）
  TMA 硬件: 自动在后台搬运
  warp 0~31: 可以去做其他事情（比如计算上一个 tile）
```

> [!tip] TMA 的优势
> - **1 条指令搬运整个 tile**：不需要循环发出多条 load 指令
> - **后台执行**：发出 TMA 指令后，warp 可以去做其他事
> - **支持 swizzle**：TMA 硬件直接输出 swizzle 后的 SMEM 布局
> - **支持 multicast**：一个 TMA 指令可以同时写入多个 CTA 的 SMEM

### 1.2 TMA 的使用方式

```cpp
// 1. 创建 TMA 描述符（host 端）
auto tma_copy_a = make_tma_copy(
    SM90_TMA_LOAD{},                    // TMA 加载操作
    mA,                                 // 源 tensor (GMEM)
    smem_layout_A(_, _, 0),             // 目标 SMEM 布局
    make_shape(Int<BM>{}, Int<BK>{}));  // tile 大小

// 2. 在 kernel 中使用
auto tma_barrier = make_barrier();  // 用于同步 TMA 完成

// 发出 TMA 请求
copy(tma_copy_a.with(tma_barrier), gA, sA);

// 等待 TMA 完成
tma_barrier.arrive_and_wait();
```

> [!important] TMA 的 swizzle 约束
> TMA 的 box 宽度必须等于一个 swizzle atom 的宽度。比如：
> - Swizzle 32B → TMA box 宽度 = 32B
> - Swizzle 128B → TMA box 宽度 = 128B
>
> 如果 tile 比 swizzle atom 大，CuTe 会自动拆成多个 TMA box。

### 1.3 TMA vs 手动搬运

```
手动搬运 (ld.global → st.shared):
  每个 warp 发出 N 条 load 指令
  每条指令搬运 16B
  总共需要 N × 32 条指令

TMA 搬运:
  1 条 TMA 指令描述整个 tile
  TMA 硬件自动完成所有搬运
  总共 1 条指令
```

## 2. Multi-Stage Pipelining

### 2.1 为什么需要 Pipeline？

朴素 GEMM 的问题是 **搬运和计算串行**：

```
朴素:
  搬运 tile 0 → 计算 tile 0 → 搬运 tile 1 → 计算 tile 1 → ...
  搬运时计算单元空闲，计算时搬运单元空闲

理想:
  搬运 tile 0 → 搬运 tile 1 (同时计算 tile 0) → 搬运 tile 2 (同时计算 tile 1) → ...
  搬运和计算重叠
```

### 2.2 双缓冲 (Double Buffering)

最简单的 pipeline：用 2 块 SMEM，一块在计算时另一块在搬运。

```cpp
__shared__ half smemA[2][BM * BK];  // 2 个 stage
__shared__ half smemB[2][BN * BK];

// stage 0: 预加载第一个 tile
copy(gA_0, sA[0]);
copy(gB_0, sB[0]);

for (int k = 0; k < num_tiles; k++) {
  int curr = k % 2;
  int next = (k + 1) % 2;

  // 同时：计算当前 tile + 搬运下一个 tile
  // 1. SMEM → RF（从 sA[curr]）
  copy_s2r(sA[curr], rA);
  copy_s2r(sB[curr], rB);

  // 2. GMEM → SMEM（到 sA[next]）
  if (k + 1 < num_tiles) {
    copy(gA_{k+1}, sA[next]);
    copy(gB_{k+1}, sB[next]);
  }

  // 3. MMA 计算
  cute::gemm(tiled_mma, rA, rB, rC);
}
```

> [!tip] 三缓冲 (Triple Buffering)
> 用 3 个 stage 可以进一步重叠：
> - stage 0: 正在计算
> - stage 1: 已经搬运完，等待计算
> - stage 2: 正在搬运
>
> 这样即使计算比搬运慢一点，也不会有 SMEM 等待。

### 2.3 Barrier 同步

Pipeline 中需要 **barrier** 来确保数据就绪：

```cpp
// 创建 barrier
auto barrier = make_barrier();

// TMA 搬运 + barrier
copy(tma_copy.with(barrier), gA, sA);

// 等待搬运完成
barrier.arrive_and_wait();

// 现在可以安全读取 sA
copy_s2r(sA, rA);
```

> [!note] Barrier vs __syncthreads__
> - `__syncthreads()`: 同步 block 内所有线程，开销大
> - `barrier.arrive_and_wait()`: 只同步 TMA 操作，更精细
> - Hopper 支持 Named Barrier，可以做更复杂的同步模式

## 3. Warp Specialization

### 3.1 什么是 Warp Specialization？

把 block 内的 warp 分成两组，各司其职：

```
Producer warp (1 个 warp group):
  专门负责 TMA 搬运（GMEM → SMEM）
  不做 MMA 计算

Consumer warp (剩余 warp group):
  专门负责 MMA 计算（SMEM → RF → 计算 → RF → SMEM）
  不做 TMA 搬运
```

> [!tip] 为什么要分开？
> - Producer 只发 TMA 指令，几乎不做计算 → 可以分配很少的寄存器
> - Consumer 做 MMA 计算，需要大量寄存器 → 分配更多的寄存器
> - 分开后两者可以各自最大化自己的资源

### 3.2 Warp Specialization 的实现

```cpp
// 判断当前 warp 属于哪一组
int warp_group_id = threadIdx.x / 128;  // 每个 warp group 128 线程（4 个 warp）

if (warp_group_id == 0) {
  // Producer: TMA 搬运
  for (int k = 0; k < num_tiles; k++) {
    copy(tma_copy_a.with(barrier[k]), gA_k, sA_k);
    copy(tma_copy_b.with(barrier[k]), gB_k, sB_k);
    barrier[k].arrive();  // 通知 Consumer 数据就绪
  }
} else {
  // Consumer: MMA 计算
  for (int k = 0; k < num_tiles; k++) {
    barrier[k].wait();  // 等待 Producer 搬运完
    copy_s2r(sA_k, rA);
    copy_s2r(sB_k, rB);
    cute::gemm(tiled_mma, rA, rB, rC);
    barrier[k].arrive();  // 通知 Producer 可以覆盖 SMEM
  }
}
```

### 3.3 寄存器分配优化

Warp Specialization 的一个关键优势是可以给不同组分配不同数量的寄存器：

```cpp
// Producer: 只需要 24 个寄存器（发 TMA 指令）
// Consumer: 需要 240 个寄存器（MMA 计算 + 中间结果）

// CuTe 中通过 warpgroup_reg_dealloc/warpgroup_reg_alloc 实现
warpgroup_reg_dealloc<24>();   // Producer 释放寄存器
warpgroup_reg_alloc<240>();    // Consumer 申请更多寄存器
```

> [!important] 寄存器分配的影响
> - Producer 用少寄存器 → 更多 warp 可以并发 → 更好的 latency hiding
> - Consumer 用多寄存器 → 更大的 tile → 更高的计算效率
> - 总寄存器数不变，但分配更合理

## 4. Cluster 与 Multicast

### 4.1 Cluster 是什么？

Cluster 是 Hopper 引入的 **多个 CTA 协作** 机制。一个 Cluster 内的多个 CTA 可以：

- 共享 SMEM（通过 TMA multicast）
- 同步（通过 cluster barrier）

```
Grid:
┌─────────────────────────────────────────────┐
│ Cluster 0:  ┌──────┐ ┌──────┐              │
│             │ CTA 0│ │ CTA 1│              │
│             └──────┘ └──────┘              │
├─────────────────────────────────────────────┤
│ Cluster 1:  ┌──────┐ ┌──────┐              │
│             │ CTA 2│ │ CTA 3│              │
│             └──────┘ └──────┘              │
└─────────────────────────────────────────────┘
```

### 4.2 TMA Multicast

TMA Multicast 让一个 TMA 指令同时写入 Cluster 内多个 CTA 的 SMEM：

```cpp
// 创建 multicast mask（哪些 CTA 需要接收数据）
auto multicast_mask = create_tma_multicast_mask(cluster_shape, cta_id);

// TMA 搬运，同时写入多个 CTA
copy(tma_copy.with(barrier).with(multicast_mask), gA, sA);
```

> [!tip] Multicast 的好处
> 如果 2 个 CTA 需要同一块 A tile：
> - 无 multicast：2 个 CTA 各自从 GMEM 读一次 → 2 次 GMEM 读
> - 有 multicast：1 个 TMA 指令写入 2 个 CTA → 1 次 GMEM 读
> → GMEM 带宽减半

## 5. 性能对比

```
朴素 GEMM:
  搬运和计算串行
  无 swizzle → bank conflict
  性能: ~30% cuBLAS

+ Swizzle:
  消除 bank conflict
  性能: ~50% cuBLAS

+ Pipeline (双缓冲):
  搬运和计算重叠
  性能: ~70% cuBLAS

+ TMA:
  硬件搬运，释放 warp
  性能: ~85% cuBLAS

+ Warp Specialization:
  Producer/Consumer 分离
  性能: ~95% cuBLAS

+ Multicast + Cluster:
  GMEM 带宽减半
  性能: ~98% cuBLAS
```

> [!note] 学习路线建议
> 1. 先理解 Layout、Tensor、TiledCopy、TiledMma（基础）
> 2. 写一个朴素 GEMM（无 pipeline、无 swizzle）
> 3. 加 Swizzle → 消除 bank conflict
> 4. 加 Pipeline → 重叠搬运和计算
> 5. 用 TMA → 替代手动搬运
> 6. 用 Warp Specialization → 分离搬运和计算
> 7. 用 Cluster + Multicast → 多 CTA 协作
