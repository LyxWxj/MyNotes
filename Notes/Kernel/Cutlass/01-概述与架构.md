# CUTLASS 与 CuTe：概述与架构

## 1. CUTLASS 是什么？

CUTLASS (CUDA Templates for Linear Algebra Subroutines) 是 NVIDIA 官方开源的 **高性能矩阵运算模板库**。它提供了一套 C++ 模板，让你能写出接近 cuBLAS 性能的 GEMM（矩阵乘法）、Conv（卷积）等算子。

> [!tip] 一句话理解
> CUTLASS 不是一个"库"（你不需要链接它），而是一个"模板集"（你 include 它的头文件，它帮你生成优化好的 CUDA kernel）。

## 2. CUTLASS 的版本演进

```
CUTLASS 1.x (2018)  → 基础 GEMM 模板，手写所有坐标计算
CUTLASS 2.x (2020)  → 支持 Tensor Core (WMMA)，更完整的抽象
CUTLASS 3.x (2023)  → 引入 CuTe，彻底重构底层抽象
```

> [!important] CUTLASS 3.x = CuTe + 上层算子
> CUTLASS 3.x 的核心变化是引入了 **CuTe** 作为底层引擎。之前版本中手写的坐标计算、padding、swizzle，全部变成了 CuTe 的 Layout 代数。

## 3. CuTe 是什么？

CuTe (CUDA Templates) 是 CUTLASS 3.x 的 **核心子库**，专门解决一个问题：

> **在 GPU 上，数据怎么排列、怎么搬运、怎么访问？**

它不关心你在算什么（GEMM？卷积？注意力？），它只关心数据的 **布局 (Layout)** 和 **搬运 (Copy)**。

```
CUTLASS 3.x 架构：
┌─────────────────────────────────────────────┐
│  上层算子（GEMM, Conv, FlashAttention）      │  ← 你要算什么
├─────────────────────────────────────────────┤
│  CuTe                                        │  ← 数据怎么搬
│  ├── Layout   (Shape + Stride + Swizzle)     │
│  ├── Tensor   (指针 + Layout = 可访问的张量)  │
│  ├── TiledCopy (分块拷贝描述符)              │
│  └── TiledMma  (分块矩阵乘法描述符)          │
├─────────────────────────────────────────────┤
│  CUDA 硬件 (SM, Tensor Core, Shared Memory)  │  ← 底层硬件
└─────────────────────────────────────────────┘
```

> [!note] CuTe vs CUTLASS 的关系
> - **CuTe** = 发动机（处理数据布局和搬运）
> - **CUTLASS** = 整辆车（用 CuTe 发动机造 GEMM、Conv 等算子）
> - 你可以单独用 CuTe 而不用 CUTLASS 的上层算子（比如写自定义 kernel）

## 4. 为什么需要 CuTe？

### 4.1 没有 CuTe 时的痛苦

写一个高性能 GEMM kernel，你需要手动处理：

```cpp
// 1. 手算每个线程访问 shared memory 的偏移
int smem_a_row = threadIdx.x / 16;
int smem_a_col = threadIdx.x % 16;
int smem_a_idx = smem_a_row * SMEM_STRIDE + smem_a_col;

// 2. 手动处理 bank conflict（加 padding）
__shared__ float tile[32][128 + 1];  // +1 padding

// 3. 手算 global memory → shared memory 的拷贝坐标
int gmem_row = blockIdx.y * BM + threadIdx.y;
int gmem_col = blockIdx.x * BN + threadIdx.x;

// 4. 手动处理向量化加载（float4）
float4 val = reinterpret_cast<float4*>(&A[gmem_row * K + gmem_col * 4])[0];

// 5. 手动处理边界检查
if (gmem_row < M && gmem_col * 4 + 3 < N) { ... }
```

每一步都容易出错，而且换一个 block size 就要全部重写。

### 4.2 有 CuTe 后的优雅

```cpp
// 1. 声明布局（形状 + 步长）
auto layout = make_layout(make_shape(32, 128), GenRowMajor{});

// 2. 创建 tensor 视图
auto tensor = make_tensor(ptr, layout);

// 3. 切出当前 block 的 tile
auto tile = local_tile(tensor, make_shape(BM, BN), coord);

// 4. 按线程分配
auto my_data = local_partition(tile, thread_layout, threadIdx.x);

// 5. 拷贝（自动处理向量化、边界）
copy_if(predicate, src, dst);
```

> [!tip] 核心区别
> CuTe 把"手写坐标"变成了"声明布局"。你告诉 CuTe "我想要什么形状"，它帮你算出"每个元素在哪里"。

## 5. GPU 内存层次与 CuTe 的对应

```
┌─────────────────────────────────────────────┐
│  Global Memory (HBM)     ← 几 GB，慢       │  gA, gB (make_gmem_ptr)
│       ↓ TiledCopy (GMEM→SMEM)              │
│  Shared Memory (SMEM)    ← 几十 KB/SM，快   │  sA, sB (make_smem_ptr)
│       ↓ TiledCopy (SMEM→RF)                 │
│  Register File (RF)      ← 几 KB/thread，最快│  tA, tB (寄存器 tensor)
│       ↓ TiledMma (Tensor Core 计算)         │
│  结果写回 SMEM → 写回 GMEM                   │
└─────────────────────────────────────────────┘
```

CuTe 的三个核心操作正好对应这三层：

| 操作 | 作用 | 对应 |
|---|---|---|
| `TiledCopy` | GMEM ↔ SMEM 搬运 | `copy(copy_a, gA, sA)` |
| `TiledCopy` | SMEM ↔ RF 搬运 | `copy(copy_s2r, sA, rA)` |
| `TiledMma` | RF 上做矩阵乘法 | `mma(mma, rA, rB, rC)` |
